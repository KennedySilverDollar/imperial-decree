## 1. 設計原則

1. **地理として嘘をつかない。** 川は高所から低所へ流れ、支流を集めて太くなり、蛇行し、氾濫原をつくる。森は標高・湿度・土壌に従って分布する。村は川沿いの段丘という「人が住む理由のある場所」に置かれる。
2. **人の営みの痕跡で語る。** 地形の上に、畑・街道・小径・集落の形が人の手で重なる。村が育つと開墾が進み、森が後退し、道が踏み固められる。
3. **測量図という文書の質感を徹底する。** 線の揺らぎ、手彩色のむら、版ずれ、注記の書体と配置、紙の経年。
4. **机の世界の光と整合させる。** 地図の陰影は机のランプの方向に合わせる（ランプは固定位置なので、ベイクで足りる。§7.4）。
5. **情報を漏らさない。** リアルに描くことが、不可視の派生指標・秘匿資材・空洞・工事の進捗の漏洩にならないようにする（§5）。
6. **決定論と建設可能性を守る。** 同じ `saveId` から同じ地図。村域100区画は常にすべて建設可能（CLAUDE.md 不変条件 18, 19）。
7. **既存実装を壊さない。** 区画の割当・道路の数・セーブ形式・テストのセレクタは変えない（§0）。

## 2. 地理設定とスケール

### 2.1 世界の枠

- 舞台は「河岸段丘の上に開かれた辺境の村」。川が村域の一辺に沿って流れ、背後に丘陵、遠くに山並みがある。
- 地図全体は約 **4km × 4km**、村域（論理グリッド）は約 **600m × 600m**。村域の外は「領地の周辺」で、段階的に粗く描かれる（§6.6）。
- 縮尺は 1区画（論理セル）＝約60m四方を既定とする（定数化。BB-01）。縮尺の注記は地図の余白に必ず入れる。
- 地図の表題（領地名）は、AA-04 に従い `Toponyms` から自動命名する。

### 2.2 建物のスケール感

- 住宅（`residential`）は1タイル＝住宅群として描く（3〜6棟の家屋、約8×10m）。容量+20の「20人分」にふさわしい密度。
- 長屋は細長い連棟、屋敷は大きな母屋と庭と塀、倉庫は大型の切妻、市場は広場と露店の並び。細部は §7.3。
- 「棟数」（V-06：1回の発注で1〜3棟）は、描画では区画内の群れの数・並びに反映してよい。ただし**棟ごとの完成・空洞は区別して描かない**（I-32）。

## 3. 地形生成 v2（Worker内、決定論）

### 3.1 パイプライン

```
seed = hash(saveId, "terrain")

1. 基礎地形      大域の標高（低周波fBm）に、山並みの方向性（リッジノイズ）を重ねる
2. 構造          主流路の谷筋を先に決め、村域を載せる河岸段丘（階段状の平坦面）を彫り込む
3. 侵食          粒子ベースの水力侵食（deterministic）＋熱侵食（斜面の崩れ）
4. 水文          流向（D8またはD∞）→ 流量累積 → 川網（本流＋支流）、蛇行の付与、氾濫原・湿地・湖沼の抽出
5. 地質ゾーン    岩盤（山地・露頭）／礫（河原）／粘土（低湿地）／ローム（段丘面・畑向き）
6. 植生          標高 × 傾斜 × 水までの距離 × 地質から、針葉樹林／広葉樹林／草地／藪／湿地植生／裸地へ分類
7. 土地利用      村域外は自然のまま（村は何もない所に開かれる）
8. 街道          外世界につながる街道（§4.4）
9. 地名          地形・植生・水系から自動生成（§6.5）
```

### 3.2 村域の保証（建設可能性）

- 村域は**河岸段丘面**に置く。段丘面は全体として緩やかな傾斜（平均3°以下）で、微起伏のみを許す。
- 村域の100区画は、**十字の道路区画（最大19）＋役所の区画（1）＋建物の区画（80）**に対応する（I-16）。
- 各区画に `slope`（度）を記録する。**100区画すべてについて水域でなく、`slope ≤ 5°` を保証**する。満たせないシードは自動で再試行する（再試行回数の上限と、同じ `saveId` で同じ結果になることを保証）。
- `slope` はゲームロジックに影響しない（建設可否・コスト・効果すべて不変）。描画（建物の向き、石垣、段差の表現）にのみ使う。

### 3.3 水文のリアリティ条件

- 川は高所から低所へ単調に流れる（局所的な窪みは湖沼として明示的に扱う）。
- 川幅は流量の関数。本流は村の近くで最大、上流は細い。支流は本流に鋭角で合流する。
- 蛇行：平坦部で曲率に応じた蛇行を付与し、旧河道（湿地として描く）を1〜2か所残す。
- 渡河点：浅瀬または橋（絵として描くのみ。建設要素ではない）。街道と川が交わる所に自動配置する。
- 氾濫原：川沿いの低平地。村域外にとどめ、段丘面との高低差（崖線）を描く。
- 川は村域の内部に入らない（v3.3-UI §5.2 から継承）。

### 3.4 解像度（二段階）

| 領域 | 解像度 | 用途 |
|------|--------|------|
| 村域（約600m四方） | 2048×2048 | 高解像度ハイトマップ。建物平面・区画の描画 |
| 周辺（約4km四方） | 1024×1024 | 低解像度。等高線・植生・水系 |

- 村域外の外縁部には、低周波の**水平方向の詳細ノイズ**を描画側で加え、解像度不足を見せない。
- ハイトマップ・法線は `Uint16Array`（または Float16 相当）で保持し、メモリを抑える。

### 3.5 地質と植生の分類

| 分類 | 条件の目安 | 描き方 |
|------|-----------|--------|
| 岩盤・露頭 | 高標高・急斜面 | ケバと岩の記号、淡い灰褐色 |
| 河原（礫） | 川沿いの氾濫原内側 | 点描の礫、薄い灰色 |
| 湿地 | 低地・水際・旧河道 | 水平ハッチングと草の記号 |
| 草地 | 中低標高の平坦〜緩斜面 | 淡い黄緑、まばらな草記号 |
| 広葉樹林 | 低〜中標高・水の近く | 丸い樹冠記号、緑 |
| 針葉樹林 | 中〜高標高・乾燥・痩せ地 | 尖った樹冠記号、濃い緑 |
| 藪 | 林縁・斜面 | 小さな点の群れ |
| 裸地 | 開墾済み・踏み固められた土 | 無地の淡い黄土 |

## 4. 土地利用・街道・集落の形

### 4.1 区画は地形に従う（割当は変えない）

- 論理グリッドの100セルは、すべて1対1で多角形の区画（`Parcel`）になる。**どのセルにどの建物が入るか、どのセルが道路か**は既存の `MapState`（W-09, I-39, I-16）が決め、本書は変えない。
- 区画の形は、v3.3-UI の「頂点ジッター＋Lloyd緩和」に加え、**段丘の縁・川・微地形の等高線**に境界が従うよう、頂点を地形に吸着させる（制約付き緩和。`d3-delaunay` を使用。AA-03 で承認済み）。
- 区画は重ならず隙間がない。

### 4.2 道路：中央の十字を「本通り」として描く

既存ロジック（I-16）では、道路は中央の十字の区画に `floor(インフラ/5)` 本（最大19）が描かれ、建物の区画を占めない。本書はこの幾何を地形に沿って描き分ける。

- **十字の区画は連なって1本の本通りの帯**になる。十字の2本の通りは、一方を段丘の縁（川）に概ね平行、もう一方を斜面・街道の方向に向ける（地形に合わせて曲げる）。
- 道路の本数が増える順（既存ロジックの順）に、本通りが交点付近から伸びる。**未整備の区画は道路にせず、踏み跡（細い破線）または何も描かない**。
- 区画境界の外では、脇道・小径は**純粋な装飾**として、可視の建物（住宅群・倉庫など）の入口から本通りへ細い線を引く。これは建物の見た目から導くもので、状態に依存しない（§5.1）。
- 道路は区画内部の建物の上を横切らない。経路は地形コスト（傾斜・水）を使った A* ＋ 曲線化（Catmull-Rom）で、等高線に沿って緩く曲がる。

### 4.3 集落の形

- 住宅群は本通りに面し、川と段丘の縁を背にして**帯状に並ぶ**ように、区画内の建物の置き方（向き・庭・塀）を決める。
- 市場は十字の交点に面する区画に広場を開く。屋敷は高台側に面して大きな敷地で描く。
- 同一カテゴリ内の位置は seed 付き乱数（`hash(saveId)` 由来。W-09）で決める。**区画の割当そのものは変えず**、区画の内側での建物の置き方だけを変える。

### 4.4 街道（外世界への道）

- 地図の外周のどこかへ向かう街道を1本置く。始点は**十字の本通りの一端**に接続し、峠または渡河点を経て地図の縁に消える。
- 街道の先は注記で「◯◯方面」とだけ書く。辺境の孤立感と外の世界とのつながりを同時に示す（地名の与え方は BB-07）。
- 街道は村の成長とともに踏み固められて太くなる（§8.1）。

### 4.5 村域外の人為物

- **置かない**（開かれたばかりの村であることを示す）。ただし古い石積み・祠・道標・獣道（細い破線）は許す。これらは状態と無関係な固定の装飾。

## 5. 情報の漏洩を防ぐ（重要）

リアルに描くほど、**秘匿された状態を絵が語ってしまう**危険がある。CLAUDE.md 不変条件 13・21・22 と DECISIONS I-32 に従い、次のルールで防ぐ。

### 5.1 地図に描いてよい / 描いてはいけない

| 事柄 | 判定 | 理由 |
|------|------|------|
| 保有している建物の種類・数・位置 | ○ | 見た目（`visual_state`） |
| 建物の密集度（建物数から導出される見た目の濃さ） | ○ | v3.2 §1.8 の三角測量で想定済み |
| 畑の広がり（`farm` の数に応じた耕作面積） | ○ | 建物の見た目。**作柄（食料の充足）は描かない** |
| 開墾による森の後退 | ○ | 建物の数と位置から決まる見た目 |
| 普請中の案件（種別・棟数・区画） | ○ | 領主自身が発注した事実（I-33）。**縄張りと足場の一様な表現のみ** |
| 普請の進み具合・残り年数・建材・労働の充足 | × | 秘匿（不変条件 13、Z-03）。進捗に応じて建物が出来ていく絵にしない |
| **空洞（hollow）の建物** | × | **I-32：地図に一切出さない。開示後も同じ見た目**。亀裂印・注記・薄い色も不可 |
| 手抜き・無理な命令（Z-06）の痕跡 | × | 秘匿 |
| 川の濁り・汚れ（衛生の表現） | × | 衛生は派生指標 |
| 煙・混雑・人影の増減（治安・人口の実態の表現） | × | 不可視の実態を暗示 |
| 住宅容量の不足を示す過密・粗末な家 | × | 住宅容量は派生指標 |
| ランダムイベントの痕跡（疫病・凶作・盗賊） | × | イベントは新聞と側近報告だけで知らせる（Z-09） |
| 地形に基づく自然（川、森、丘） | ○ | 状態と無関係 |

### 5.2 投影型で構造的に守る

地図の描画層は `GameState` 全体を受け取らない。専用の投影型だけを受け取る。

```ts
type MapViewModel = {
  turn: number;                       // 測量年
  parcels: ParcelView[];              // 100区画（割当は MapState のまま）
  roads: RoadView[];                  // 道路区画（整備済みの分のみ）
  buildings: BuildingView[];          // 種類・区画・棟数・完成した年（空洞の有無は含めない）
  construction: ConstructionView[];   // 普請中：種別・区画・棟数のみ（進捗・工期・建材は含めない）
  notes: PlayerNote[];                // メモ（留め先のある分のみ）
  surveyedUntil: number;              // 測量の遅れフラグ有効時のみ意味を持つ（既定無効）
};
```

- `projectMapView(state)` は、空洞フラグ・派生指標・資材・工事の進捗・イベントを**読まない**。
- 描画層（`src/ui/map/`）は `GameState`・`DerivedStats`・`Construction`・`Events` を import しない。ESLint の `no-restricted-imports` と依存関係テストで検査する（§12.3）。
- `disclosedAnomalies`（旧案）は**廃止**。

様式は「近代初期の官製測量図」。紙に墨の線と水彩の淡彩で描かれ、手仕事の揺らぎがある。

### 6.1 レイヤ

| 順 | レイヤ | 内容 | 更新 |
|----|--------|------|------|
| 1 | 紙 | 羊皮紙〜和紙風の地、繊維、染み、折り目の線と摩耗、縁の焼け | 生成時 |
| 2 | 地質の下塗り | 地質・植生の淡い水彩ベタ塗り（むらあり、縁がにじむ） | 生成時 |
| 3 | 陰影 | ヒルシェード（ランプ方向でベイク）＋ケバ（斜面の短い線） | 生成時 |
| 4 | 等高線 | 細い茶の線、5本ごとに太い計曲線、標高注記、線の揺らぎ | 生成時 |
| 5 | 水系 | 川は青インクの外形線＋内側の淡い水彩（川幅で濃さが変わる）、湖はハッチング、湿地は水平線と草記号 | 生成時 |
| 6 | 植生 | 樹冠記号の点描（シード付き、広葉樹・針葉樹・藪・草を描き分け） | 生成時＋開墾時 |
| 7 | 土地利用 | 街道、獣道、石積み・祠、開墾地 | 生成時＋成長時 |
| 8 | 区画 | 境界は細い破線、畑は耕作の縞（畝の向きは地形に従う）、空き地は草の気配 | 毎ターン |
| 9 | 道路 | 本通り（十字の帯）、装飾の脇道・小径 | 毎ターン |
| 10 | 建物 | 低倍率は絵記号（当面 `tileGlyphs`、AA-12）、高倍率は建物平面（§7.3）。普請中は縄張りと足場 | 毎ターン |
| 11 | 注記 | 地名・川名・山名・標高点・方位・縮尺・表題・測量年・凡例 | 生成時＋毎ターン |
| 12 | 書き込み | プレイヤーのメモ、測量の遅れの注記（フラグ有効時のみ） | 毎ターン |

> 旧案にあった「亀裂印」は**廃止**（I-32）。

### 6.2 手仕事の揺らぎ

- 線は一定の太さにしない。筆圧に相当する太さの揺らぎと、わずかな手ぶれ（低周波ノイズで線をずらす）を入れる。
- 彩色は**版ずれ**（色面が線画から0.5〜1.5px ずれる）、色のむら、水彩の縁のにじみを再現する。
- 可読性を最優先し、揺らぎは文字・記号の判別を妨げない範囲に抑える。

### 6.3 ケバと等高線の併用

- 緩斜面は等高線と淡い陰影、急斜面はケバ（短い線を斜面の最大傾斜方向に並べる）で描く。
- ケバの密度と太さは傾斜に比例する。崖線（段丘の縁）は特に明瞭に描く。
- 等高線とケバが重なるときは、等高線を優先して線を間引く。
- 等高線は marching squares を**自前で実装**する（`d3-contour` は未承認。使う場合は DECISIONS に1行記録して許可を得る。BB-06）。

### 6.4 水彩の配色（v3.0 §12.3 の方針：彩度低め、朱のみアクセント）

| 用途 | 色 |
|------|----|
| 広葉樹林の塗り | `#8FA06A` |
| 針葉樹林の塗り | `#6F8260` |
| 草地の塗り | `#B9BE8A` |
| 湿地の塗り | `#A4B59A` |
| 河原の塗り | `#C9C3B0` |
| 岩盤・露頭の塗り | `#B3A898` |
| 開墾地（裸地）の塗り | `#D2BF93` |
| 耕作地（畑）の縞 | `#8A7440`（線）＋`#CDBB82`（地） |
| 川の外形線 | `#4F6B7A` |
| 川の水彩（浅い→深い） | `#B7CBCF` → `#8FAAB3` |
| 街道・本通りの塗り | `#CBB98E`（外形線 `#5C4A35`） |

v3.3-UI §5.4 の測量図専用パレット（低地・中腹・高地の淡彩、等高線、水系など）は継承する。

### 6.5 文字（注記）

- 書体：地名・川名・山名は AA-02 で確認する書体（しっぽり明朝 B1 の細字を候補）、標高・縮尺・凡例は Noto Serif JP。
- 配置：川名は川の曲線に沿わせ、山名は文字間隔を広げて稜線方向に、区画名は水平。重なる文字は優先度（川名 > 山名 > 地名 > 区画名）で間引く。
- 縮尺ごとに表示する注記を切り替える。
- 地名は新聞の `{place}` と共有する（不変条件 20）。地名一覧は新聞生成より前に確定させる。

### 6.6 測量範囲の濃淡

- 村域とその周辺は精細に、外縁は粗く（等高線の間隔を広げ、植生記号を疎に、文字を少なく）描く。外縁近くは「未測」の注記と薄い彩色にとどめる。
- この濃淡は**見た目**であり、ゲームロジックに影響しない。

### 7.1 ズーム段階（LOD）

| 段階 | 範囲 | 描くもの |

| L0 全域 | 約4km | 山・川・森・街道・村域の輪郭。注記は山名・川名 |

| 農地 | 畝の方向（地形に沿う）、畦、小屋 |

### 7.4 光と陰影（ベイク方式）

- ランプは机の固定位置なので、地図の陰影は**固定の光源方向でベイク**する（Worker で標高と法線からヒルシェードを生成し、`ImageBitmap` としてテクスチャ化。AA-09 の方式に合う）。
- 窓の光（天候色、v3.3-UI §3.4）は、地図全体の**色温度の薄い重ね塗り**（乗算オーバーレイ）としてランタイムで加える。シェーダは使わない。
- 光源方向を動かす演出は行わない（必要になったら BB-05 のスパイクで WebGL 化を再検討）。

## 8. 成長・普請・経年

### 8.1 成長の痕跡（建物 → 土地利用）

| 契機 | 描画の変化 |
|------|------------|
| `farm` が完成する | 村の周辺で森が後退し、耕作の縞が広がる（開墾） |
| `residential` / `tenement` が完成する | 本通り沿いに住宅群が帯状に伸びる |
| `road`（インフラ）が増える | 本通りの帯が既存ロジックの順に整備されていく。装飾の脇道・小径が枝を伸ばす |
| 年数（ターン）が進む | 街道が踏み固められて太くなる。村域周辺の草地が裸地に近づく |
| `market` が完成する | 十字の交点に広場が開ける |

- 開墾の範囲は、完成した `farm` の数と位置から**決定論的に**求める。村域の外へ最大で数十メートル広がる程度で、建設可能性には影響しない。
- 成長の見た目は、**完成した建物**という可視の事実からのみ導く。食料・作柄・資材などの秘匿の実態は示さない（§5）。

### 8.2 普請中の表現

- 発注した案件の区画には、「普請中」の一様な表現（縄張り・足場・資材置きの気配）を描く（Z-13, I-33）。
- **進捗に応じた段階的な建物の出来上がりは描かない**（進捗が漏れる）。完成した年にはじめて建物が現れる。
- 手抜き・無理な命令による空洞化は、完成後も見た目に出さない（I-32）。

### 8.3 紙の経年

- ターン（年）が進むと、地図用紙が少しずつ古くなる（黄変、折り目の摩耗、縁の傷み）。**可読性は落とさない**。
- 今ターンに描き込んだ線は濃く新しい墨、過去の線は褪せた墨。

### 8.4 インクの描き込み（演出）

- 新しい道（本通りの区画）は、細い点線のあとに本通りの線が描き込まれる。
- 完成した建物は、外形線 → 屋根の線 → 着彩の順に描き込まれる（完成した年の**一度きりの演出**。進捗の表現ではない）。
- 開墾は、森の樹冠記号が間引かれ、耕作の縞が薄く広がる。
- 「動きを減らす」設定では即時描画に置き換える（不変条件 24）。

## 9. 性能・生成予算・フォールバック

| 項目 | 目標 |
|------|------|
| 新規ゲーム開始時の地形生成 | **3.0 秒以内**（Worker、進捗は「測量中」の演出で隠す）。**スパイク S-2 を侵食・水文込みで再計測**して確定（BB-03） |
| ロード時の再生成 | 同上（seed から再生成） |
| 手元でのパン・ズーム | 60fps（統合GPU相当）。タイルキャッシュで再描画を最小化 |
| 初回の絵記号・テクスチャ読込 | 追加 3MB 以内（絵記号は SVG、地質・紙は手続き生成） |
| メモリ | 地図全体で 200MB 以内 |

- **ベイク戦略**：静的レイヤ（紙・地質・陰影・等高線・水系・植生）は、Worker で LOD ごとのタイルにベイクしてキャッシュ。毎ターン変わる部分（区画・道路・建物・普請中・書き込み）だけをランタイムで描く。
- **フォールバック（既存の抽象グリッドを残す）**：地形生成が未完了・失敗・タイムアウトのときは、**現行の抽象10×10グリッド描画**（`MapScene` の既存実装）を表示する。ゲームは止まらない。平面モード（AA-08）でも同じ地図を使う。
- **自動縮退**：45fps を下回る状態が一定時間続いたら、ケバの細部・注記の一部・重ね塗りを省略する（視差・ぼかしの自動停止は v3.3-UI と共通）。
- **スクリーンショット用**：地形生成の完了を示す属性（例：`data-terrain-ready="true"`）を地図パネルに付け、`scripts/screenshots.cjs` が待てるようにする（AA-14。既存のセレクタは変えない）。

## 10. 地形模型モード（任意・仕様変更提案）

同じ地形を**立体の地形模型**として見るモード。執務室に領地の石膏模型が置かれている、という机の物体として表す。

### 10.1 位置づけ

- 優先度：**任意（M4）**。測量図（M1〜M3）の完成とプレイテストの反応を見てから判断する。
- **P0 の対象外**：CLAUDE.md §10「Three.js による完全3D／ジオラマは対象外」、AA-06「製品版のジオラマ表現は P0 の結果次第」。着手するには**スコープ変更の承認**が必要（BB-04）。

### 10.2 表現

- 標高を高さに変換した格子メッシュ（村域は高密度、周辺は低密度）。石膏の素材。
- 川・湖は半透明の薄い面、森は低ポリの樹木またはテクスチャ、建物は簡易ボリューム。
- 光は机の光源（ランプ）と整合。
- 地図と同じ `MapViewModel` を共用する（§5.2）。**空洞・進捗は表現しない**。

### 10.3 技術上の注意

- Three.js（MIT）を使う場合は、この小さなキャンバス内に限る。代替は CANVAS 上の擬似3D（等角投影の等高線ブロック）で、工数は小さいが立体感は劣る。採否は M4 着手前に DECISIONS で判断する。
- 平面モード・性能不足環境では無効にし、測量図のみとする。

### 11.1 型

```ts
type TerrainDataV2 = {
  seed: number;
  village: { heightmap: Uint16Array; normal: Uint16Array };   // 2048²
  surround: { heightmap: Uint16Array };                        // 1024²
  rivers: River[];            // 本流・支流、幅（流量由来）
  lakes: Polygon[];
  wetlands: Polygon[];
  geology: Uint8Array;
  vegetation: Uint8Array;
  highway: Polyline;          // 外世界への街道（十字の一端に接続）
  fords: Point[];             // 渡河点
  parcels: Parcel[];          // 100区画（セルと1対1、slope 付き）
  toponyms: Toponym[];
};

type Parcel = {
  gridIndex: number;          // 0..99（MapState のセルと一致）
  polygon: Point[];
  name: string;
  slope: number;              // 度。ロジックには影響しない
};

type River = { points: Point[]; widths: number[]; name: string };
```

- セーブには `seed`（`saveId` から導出）だけを保存し、`TerrainDataV2` はロード時に再生成する（不変条件 18）。`PlayerNotes` は別キーに保存（AA-11）。

## 12. テスト

### 12.1 地形・水文（Node 環境の純関数テスト）

- 決定論：同じ `saveId` で `TerrainDataV2` のハッシュが一致
- 村域100区画が**すべて水域でなく、`slope ≤ 5°`**（シード1000個の検証。`npm run terrain:check`。DECISIONS S-3 のスパイクを引き継ぐ）
- 川が単調に下流へ流れる（窪みは湖として扱われている）、本流が地図の縁または湖で終わる
- 川が村域の内部に入らない
- 蛇行・旧河道の条件、街道が十字の一端から地図の縁まで到達する

### 12.2 区画・道路・建物

- 区画が重ならず隙間がない、すべて論理セルと1対1（`MapState` のセルと `gridIndex` が一致）
- **本通り（十字の区画）が連続した帯になり**、道路の描画本数が `floor(インフラ/5)`（最大19）と一致
- 道路が区画内部の建物を横切らない
- 建物平面が区画多角形の内側に収まり、互いに重ならない／同じ建物IDで常に同じ平面
- 17種すべての建物平面が描ける

### 12.3 情報漏洩（最重要）

- `src/ui/map/` が `GameState`・`DerivedStats`・`Construction`・`Events` を import していない（ESLint ＋ 依存関係テスト）
- `projectMapView(state)`：同じ可視状態で、**空洞フラグ・資材・工事の進捗・派生指標・イベントだけが違う**2つの状態から、同じ `MapViewModel` が得られる
- 普請中の表現が、進捗・工期によって変化しない
- 開墾・密集度・建物平面が、可視の建物（完成した建物）のみに依存する

### 12.4 描画・性能

- 地形生成が 3.0 秒以内（計測値を報告。スパイク S-2 の結果を記録）
- L0〜L3 でラベルの重なり・欠けが許容範囲内（スクリーンショットの目視）
- 地形生成の失敗・タイムアウト時に、既存の抽象グリッドにフォールバックする
- 平面モードと3Dモードで地図の表示情報が同一
- `prefers-reduced-motion` で描き込み演出が短縮される

### 12.5 KPI（追加）

- ズーム段階（L0〜L3）の使用分布、L3 の滞在時間
- 区画ホバー・クリック、メモ留め先（地図）の回数
- 「地図の見た目と報告の食い違い」への言及回数（P4 の思考発話）
