# 追加仕様書 v3.1-AMENDMENT『勅令都市（仮）』

> 位置づけ：v3.0 FINAL に対する差分仕様。**本書の決定事項は v3.0 の該当章を上書きする。**
> 対象：プロトタイプ（P0）実装に影響する10項目のみ。
> 本ファイルはユーザーから受領した原文の転記（表記のみ Markdown に整形）。実装上の解釈・矛盾の指摘は `docs/DECISIONS.md` §6 に書く。

## A-01. 政治資本の収入とボーナス（v3.0 §7.1, §6.2 を上書き）

| 項目 | v3.0 | v3.1（決定） |
|------|------|--------------|
| 収入 | +3/ターン | **+1/ターン** |
| 上限 | 10 | **5** |
| 勅令発行コスト | 1 | 1（変更なし） |
| 任命コスト | 1 | 1（変更なし） |
| 解任コスト | 0 | 0（変更なし） |
| 意図達成ボーナス | 政治資本+1 または 幸福度+5 | **幸福度+5 に固定** |

理由：政治資本を希少資源化し、「勅令を出すか側近を交代するか」の選択を生む。ボーナスは政治資本と別軸の報酬にする。

## A-02. バランス検証の目標値（v3.0 §9.2, §9.3, §15 を上書き）

| 指標 | v3.0 | v3.1（決定） |
|------|------|--------------|
| ランダム勅令sim到達率 | 30〜50% | 下限参考値として記録（合否判定には使わない） |
| ヒューリスティック方策sim到達率 | 未定義 | **70〜90%（合否判定の主指標）** |
| 人間の初見到達率 | 30〜50% | **50〜70%（P4で実測）** |
| ゲームオーバー率 | 20〜40% | 20〜40%（変更なし、内訳はA-08で調整） |

理由：人間はランダムより上手いため、ランダム30〜50%は高難度設定として低すぎる。simは人間に近いヒューリスティックで評価する。

## A-03. target の固定 enum（v3.0 §11.2, §11.4 を上書き）

target は以下の8種類の enum に固定する。自由文字列は禁止。

```ts
type Target =
  | "residential"  // 住宅
  | "road"         // 道路
  | "well"         // 井戸
  | "office"       // 役所
  | "market"       // 市場
  | "tax"          // 税
  | "welfare"      // 福祉
  | "security";    // 治安
```

Structured Outputs の JSON Schema に enum として埋め込み、表記ゆれを排除する。

## A-04. 精度式の境界（v3.0 §7.6 を上書き）

`>` を `>=` に変更する。

```
accuracy = clamp(0.3 + ability/200
              + (専門一致 ? 0.2 : 0)
              + (信頼 >= 70 ? 0.1 : 0)
              - (野心 >= 70 && 派閥対立 ? 0.2 : 0), 0, 1)
```

理由：側近Aの信頼70・側近Bの野心70が境界に一致し、初期状態で両項が無効化されるのを防ぐ。

---

## A-05. 担当側近の選択（v3.0 §11.5 を上書き）

- 自動選択とする。優先順位：①専門一致 → ②信頼関係の高い順。
- プレイヤーに宛先を選ばせない（製品版で追加）。
- 3段表示に「選ばれた側近」と「選定理由」を明示する。

理由：P0の検証仮説は「勅令の文案の難しさ」であり、宛先選択は注意力を分散させる。

## A-06. タグの種類と文字数コスト（v3.0 §6.1 を上書き）

| 項目 | v3.0 | v3.1（決定） |
|------|------|--------------|
| タグ種類 | 対象/規模/期限/優先度 | **対象/規模の2種類のみ** |

| タグ1つの文字数コスト | 5文字 | **3文字** |

## A-07. 予算不足時の支出（v3.0 §8, §11.5 を上書き）

- 国庫が不足する場合、規模を国庫に合わせて自動縮小する。
- 役所（office）のみ不成立（縮小ではなく実行不可）。
- 縮小・不成立は3段表示の「側近による補正」欄に明示する（例：「予算不足のため規模を50%縮小」）。

結果：ゲームオーバーは主に維持費・給与の積み重ねによる財政破綻となる（内訳調整はA-08）。

---

## A-08. ゲームオーバー経路の確保（v3.0 §7.2 を上書き）

財政破綻偏重を是正するため、以下のペナルティを追加する。

| 追加ルール | 効果 |
|------------|------|
| 増税系の勅令（tax + 正の magnitude） | 幸福度ペナルティ（magnitude に比例） |
| 住宅不足（人口 > 住宅区画数 × 20） | 幸福度ペナルティ（毎ターン） |
| 汚職率の放置（汚職 > 50） | 幸福度ペナルティ（毎ターン） |

これにより「財政は持つが民衆が離反」「幸福度0→人口流出→人口0」の経路が現実的に発生する。

---

## A-09. LLMへの入力（v3.0 §11.2, §11.5 を上書き）

- LLMに渡すのは勅令本文とタグのみ。GameState（パラメータ・側近・履歴）は渡さない。
- システムプロンプトには target の8 enum と action の6 enum を固定で含める（語彙定義であり状態ではない）。
- プロンプトインジェクションの攻撃面を縮小し、解釈の状態依存を排除する。
