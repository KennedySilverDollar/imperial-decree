## 1. 新聞システム v2

### 1.1 設計原則

1. **LLMを使わない**（v3.0踏襲）。テンプレート＋スロット＋シード付き乱数で生成し、決定論を保つ。
2. 新聞は「世論と事件の唯一の情報源」。特に派生指標（住宅容量・食料・衛生・治安・行政能力）は台帳に載らず、新聞と側近報告でしか知れない。
3. 偏向は3層：新聞社の**思想的偏向**、**検閲**、**官僚の圧力**。それぞれ効く記事種別が異なる。
4. 投書欄は「乖離のにおわせ」装置。`actual_state` の空洞化や側近の隠蔽を、断言ではなく住民の声として滲ませる。
5. **継続スレッド**を持つ。同じ問題が2〜3ターンにわたり追跡され、プレイヤーの注意を引く。

### 1.5 偏向・検閲・官僚圧力のモデル

| パラメータ | 範囲 | P0固定値 | 効果 |
|------------|------|----------|------|
| 思想的偏向 | 0–100 | 30 | 経済・社会面の論調を派閥方向に寄せる |
| 検閲 | 0–100 | 20 | 負の記事（N-02/04/05/06/14/16）を矮小化・削除 |
| 官僚圧力 | 0–100 | 10 | 行政面（N-11/13）を抑圧・称賛に転換 |

**変換ルール**（記事生成時に適用）：

1. **数値のヘッジ**：`bias/100` の確率で正確な数値を `{hedge}` 付き曖昧表現に置換。
2. **婉曲化**：負の変化は euphemism テーブルで言い換え（減少→横ばい、汚職→手続きの遅れ）。
3. **削除**：`censorship/100` の確率で負の記事を削除し、フレーバー記事（N-18/19）で穴埋め。
4. **称賛転換**：行政面の負の記事は `bureaucratic/100` の確率で称賛記事に反転。
5. **信頼性の痕跡**：ヘッジ・婉曲の頻度が高いほど「この紙は怪しい」とプレイヤーが推測できる。**信頼性数値は直接表示しない。**

### 1.6 生成アルゴリズム（決定論）

```
seed = hash(saveId, turn)
rng = seededPRNG(seed)

1. アクティブなスレッドを優先的に記事化（最大2件）
2. セクションごとにトリガー条件を満たすテンプレートを収集
3. 重み付き抽選（直近3ターンで使用したテンプレートは重み0.3倍）
4. スロットを実状態から埋める
5. 偏向変換を適用（1.5のルール）
6. 記事数が5未満ならフレーバー（N-18/19/20）で補充
7. 紙面レイアウト順にソートして返す
```

**決定論の保証**：同じ `saveId`・同じ `turn`・同じ状態なら常に同じ紙面。テストで検証する。

### 1.7 継続スレッド

| threadKey | 発生 | 継続 | 解消 |
|-----------|------|------|------|
| `corruption` | N-11 発生 | 2〜3ターン | 汚職率<20 or 裁判所稼働 |
| `granary_hollow` | 倉庫の `actual_state` 空洞化 | 2〜3ターン | 監査 or 側近報告で露見 |
| `aide_ambition` | 側近の野心>70 | 2ターン | 解任 or 信頼回復 |
| `housing_crisis` | 住宅不足 | 住宅容量が人口を上回るまで | — |

スレッドは投書欄（N-16/17）と連動し、**「新聞が黙っていても投書が騒ぐ」**という情報経路を作る。

### 1.8 側近報告との突合（三角測量）

プレイヤーは新聞・側近報告・地図を突き合わせて真実に近づく。代表例：

| 事実 | 新聞 | 側近報告 | 地図 |
|------|------|----------|------|
| 倉庫が空洞 | 投書「物が入っていないらしい」 | 能力高Aは言及、野心高Bは隠す | 倉庫タイル（亀裂は未表示） |
| 汚職進行 | 行政面が「手続きの遅れ」と婉曲化 | 忠誠高Aは報告、Bは無言 | 変化なし |
| 幸福度低下 | 検閲で「横ばい」 | 信頼低だと報告減 | 住宅タイルの密集 |

> 設計意図：どの情報源も単独では真実を語らない。2つ以上の食い違いに気づくことが「情報を反芻する」体験の具体化。

### 1.9 乖離の「におわせ」

- `actual_state` が空洞・塩漬けの建物は、投書欄（N-16）で**断言せずに滲ませる**。
- 例：「新しい倉庫は立派だが、荷車が出入りしているのを見たことがない」
- 検閲値が高いと投書が削除され、新聞から乖離の手がかりが消える。その場合、側近報告（能力高）だけが頼りになる。

## 2. 建物レパートリー拡張

### 2.1 二層構造

```
カテゴリ（6）：住宅 / インフラ / 経済 / 行政 / 社会 / 治安
   └─ 建物（17）：target enum
政策（3）：税率 / 福祉政策 / 治安政策
```

`target` enum は建物17＋政策3＝**20種類**。v3.1 A-03 の8種類を差し替える。Structured Outputs の enum に20個を列挙する（Mistral の JSON Schema で扱える規模）。

### 2.2 パラメータ可視性

- **台帳（可視）**：人口・国庫・幸福度・インフラ・汚職率・政治資本。領主の記録として常時表示。
- **派生指標（不可視）**：住宅容量・食料・衛生・治安・行政能力。新聞と側近報告でしか知れない。

この区別により、新聞の価値が「フレーバー」から「推測の材料」に上がる。

### 2.4 トレードオフ設計の原則

どの建物も「万能」にしない。必ずコア指標と派生指標の間でトレードオフを発生させる。

- 長屋：容量は大きいが幸福・衛生を下げる
- 屋敷：税収は大きいが幸福を下げ、前提人口が必要
- 工房：税収は大きいが衛生を下げる
- 徴税所：税収は大きいが幸福を大きく下げる
- 牢屋：治安は上がるが幸福を下げる
- 裁判所：汚職を下げるが維持費が高い
- 学校：効果が長期（行政能力は遅れて効く）

これにより「何を建てるか」の判断に、短期の国庫と長期の派生指標の両面が絡む。

### 2.5 派生指標の計算式（初期案、P4で調整）

```
住宅容量 = 20*residential + 35*tenement + 10*manor
食料     = 4*farm + 2*granary
衛生     = 3*well + 2*clinic - 2*workshop
           - max(0, (人口 - 住宅容量) / 50)
治安     = 3*watchtower + 4*jail + 2*temple
           - max(0, (人口 - 住宅容量) / 50)
行政能力 = 1*office + 0.5*school   // 側近精度に +0.05*admin（上限+0.15）
```

（式中の建物名は各建物の保有数）人口増加と幸福度のドリフトは、上記の派生指標と税負担・汚職から算出する。具体的な係数は P4 でシミュレーション調整。

### 2.6 自動配置ルールの更新

10×10＝100タイルへの配置優先順位：

```
1. office（役所、1区画固定）
2. road（floor(インフラ/5)、最大20）
3. 住宅系（residential/tenement/manor、人口容量に応じて）
4. 経済系（market/farm/workshop）
5. 社会系（clinic/school/temple）
6. 治安系（watchtower/jail）
7. インフラ系（well/granary）
8. 空き地（残余）
```

同一カテゴリ内はシード付き乱数で配置。カテゴリごとにタイル色を変え、アイコンで建物種別を表示する（彩度は v3.0 §12.3 のパレットに従う）。

### 2.7 勅令の幅（例文集）

| 勅令本文 | タグ | 文字数（元記載） |
|----------|------|------------------|
| 「長屋を三つ建てよ」 | target=tenement, scale=medium | 15 |
| 「井戸を整備せよ」 | target=well, scale=small | 14 |
| 「市場を開け」 | target=market, scale=small | 11 |
| 「役所を建てよ」 | target=office | 12 |
| 「徴税所を置き税を取れ」 | target=taxoffice, scale=medium | 17 |
| 「裁判所を建て汚職を裁け」 | target=courthouse | 18 |
| 「学校を建てよ」 | target=school | 12 |
| 「牢屋を建て治安を守れ」 | target=jail | 17 |
| 「税率を上げよ」 | target=tax_rate, scale=medium | 14 |
| 「福祉を厚くせよ」 | target=welfare_policy, scale=medium | 14 |

> ※「文字数」列は元記載のまま。v3.0 の文字数式（タグ1つ5文字）と合わない（§5 #3 参照）。例文としてのみ扱う。

設計意図：建物が増えたことで、同じ「建てよ」でも対象次第で効果が大きく異なる。文字数制限下で「何を建てるか」を選ぶ判断が、v3.0 の検証仮説をより深くする。

### 2.8 バランスレバー

| レバー | 調整幅 | 影響 |
|--------|--------|------|
| 建物の建設費・維持費 | ±50% | 財政破綻の頻度 |
| 派生指標の係数 | ±50% | 幸福度・人口増加の感度 |
| 行政能力の精度寄与 | 0.03〜0.1 | 役所・学校の価値 |
| 汚職の空洞化確率 | 0〜30% | 倉庫・市場のリスク |
| 住宅不足ペナルティ | 0〜-5/ターン | 幸福度経由のゲームオーバー |

## 3. 既存仕様への影響

### 3.1 スコープ・スケジュールへの影響

| フェーズ | 追加作業 | 目安 |
|----------|----------|------|
| P1 | enum拡張、派生指標の計算、記事スキーマ | +3〜5日 |
| P2 | テンプレート24本、建物タイル17種、台帳UI、派生指標は非表示 | +5〜7日 |
| P4 | バランス調整（建物・派生指標・新聞の偏向） | 変更なし（調整項目増） |

合計で約2週間の延長を見込む。プロトの検証仮説（勅令の難しさ）は強化されるが、バランス調整の工数が増える点はリスクとして認識しておく。

### 3.2 追加KPI

- 新聞の平均閲覧時間（長いほど情報を読んでいる）
- 投書欄の参照率（乖離のにおわせに気づいているか）
- 建物種別の使用分布のエントロピー（偏り＝幅が活きていない）
- 派生指標の推測正答率（テスターに「住宅容量は足りていると思うか」と聞く）

### 3.3 追加テスト要件

- 派生指標が負にならない（property-based test）
- `target` enum の全20種が Structured Outputs のスキーマ検証を通る
- テンプレートのスロットがすべて埋まる（未定義スロットで `Effect.die`）
- 同じシードで同じ紙面が生成される（決定論テスト）
- 偏向変換後も記事本文が空にならない

## 5. 整理時に見つけた不整合・未定義（要判断）

実装前に `docs/DECISIONS.md` で決める。推奨案は暫定。

| # | 論点 | 内容 | 推奨案 |
|---|------|------|--------|
| 1 | v3.1 の参照 | 本書は v3.1-AMENDMENT を前提とするが、整理時点で v3.1 本文を参照できていない | `docs/SPEC_v3.1.md` を併置し、衝突は本書優先 |
| 2 | 初期建物の有無 | 初期人口120に対し住宅容量0、衛生0、治安0（閾値 `<3`）。**ゲーム開始直後から N-05/06/14 が発火**する | 初期建物セット（例：住宅6、井戸1、道路2）または各指標のベースライン値を定義 |
| 3 | 例文の文字数 | §2.7 の文字数が v3.0 の式（`text.length + tags.length*5 <= 40`）と合わない（元記載は「タグ3×2=6込み」と読める） | 例文は参考扱い。文字数は式から機械計算し、例文集は再計算して差し替え |
| 4 | 派生指標が負になりうる | 式（衛生・治安）は負値を取りうるが、テスト要件は「負にならない」 | 派生指標は `max(0, …)` でクランプ。トリガー判定もクランプ後の値で行う |
| 5 | 食料・治安の効果 | 食料と治安は新聞トリガー以外の効果が未定義（飢餓・犯罪が何を動かすか不明） | 幸福度・人口流出への寄与として BALANCE.md に定義 |
| 6 | 建設数の決め方 | 「長屋を三つ」のような数量の扱い、建設費・維持費の課金タイミング、1ターンの建設上限が未定義。v3.0 の「人口から区画を導出」方式（§8.2）とも整合が必要 | `magnitude` を建設数に写像。区画は「保有建物」から配置し、人口導出は廃止 |
| 7 | タイル数の上限 | 100タイルに対し、道路（最大20）＋全建物が収まる保証がない | 満杯時は建設を拒否（または優先度の低い区画が溢れる）。ルールを決める |
| 8 | action と target の組合せ | `action`（build/tax/invest/reform/appoint/dismiss）× `target`（20種）の有効組合せ表がない（例：`build`×`tax_rate`） | 有効組合せ表を定義し、無効は no-op＋側近報告で「意味が取れなかった」 |
| 9 | 前提未達時の挙動 | 前提（役所、見張り塔、人口≥200）未達の勅令の扱いが未定義 | 国庫は消費せず no-op、側近報告で理由を返す |
| 10 | 記事数 | セクション別の記事数の合計は 5〜9 になりうるが、総数は 5〜7 とある | 上限7で打ち切る（優先度：スレッド→第一面→負の記事→フレーバー） |
| 11 | テンプレート本数 | 記事IDは N-01〜N-20 の20種だが、総数は24本。差分の4本（バリエーション）の内訳が不明 | バリエーションの割当（例：N-01/09/16/18 に各+1）を P2 着手時に決定 |
| 12 | N-20 のセクション | セクションが未記載 | 社会面（人口動態）を推奨 |
| 13 | 状態に持つべきもの | 継続スレッドの進行状況と「直近3ターンの使用テンプレ」は決定論のため `GameState` に保存が必要 | `GameState.newspaperState`（threads, recentTemplates）を追加 |
| 14 | 税・維持費の単位 | 「税+5」「維持費2」が毎ターンの国庫増減なのか単位が未記載 | 毎ターン（1年）の国庫増減として BALANCE.md で明記 |
