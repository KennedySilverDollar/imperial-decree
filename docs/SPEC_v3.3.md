## 1. 設計原則

1. **机の上の「もの」を扱う。** 画面はUIパネルの集まりではなく、執務机に置かれた物体の集まり。新聞・書簡・地図・台帳・勅令用紙・判子は、それぞれ厚み・影・重なりを持つ。
2. **俯瞰で全体を見て、手に取って読む。** 机全体を斜め上から見る「俯瞰」と、1つの書類を手前に引き寄せて正対させる「手元」の2つの視点を往復する。読む・書く・操作するのは常に手元で行い、文字の可読性と入力精度を守る。
3. **地図は「測量図」という文書である。** 地図は神の視点の画面ではなく、測量官が描いた一枚の紙。地形・川・森は実在の地理として描かれ、区画と建物はインクで描き込まれる。
4. **決定の重みを身体感覚で伝える。** 筆記、封蝋、判子、書類の束ね、配達。1ターンの区切りを物理的な所作の連なりとして演出する。
5. **情報の不確かさを紙の上に表す。** 婉曲・ヘッジ・隠蔽は、文面だけでなく書類の状態（インクの滲み、測量の日付、書き込みの新旧）にも現れる。ただし信頼性の数値は表示しない（v3.2 §1.5 踏襲）。
6. **ロジックと表現を分離する。** 表現層はゲーム状態を読むだけで、状態を変えない。同じ状態からは同じ机・同じ地図が描かれる（決定論）。

## 2. 技術方式

### 2.1 方式の比較

| 方式 | 概要 | 長所 | 短所 |
|------|------|------|------|
| A. 完全3D（Three.js / react-three-fiber） | 机・紙・照明をすべて3Dで描画 | 実照明・実影、最も立体的 | 文字の可読性が落ちる、テキスト入力が難しい、工数とGPU負荷が大きい |
| **B. CSS 3D＋WebGL地図（推奨）** | 机と書類をDOM＋CSS 3D変形で構成。地図のみ WebGL（Phaser）で描き、机の上にテクスチャとして置く | 文字が鮮明、DOMの入力・アクセシビリティをそのまま使える、統合GPUで軽い、既存スタックを維持 | 照明は擬似表現、遠近下の地図操作に工夫が必要 |
| C. 2Dイラスト＋視差 | 机を描き込んだ1枚絵＋パララックス | 最軽量 | 立体感と操作感が弱い |

**採用：B。** 俯瞰では書類をCSS 3Dで机上に寝かせて置き、手に取ると正対（変形なし）になるため、遠近変形下での入力・可読性の問題を構造的に回避できる。

### 2.2 レイヤ構成

```
[DeskStage]  DOM, perspective: 1600px 前後
  ├─ 机の天板（木目テクスチャ＋擬似照明グラデーション）
  ├─ 机上オブジェクト（DeskObject × N）  CSS transform: rotateX / rotateZ / translateZ
  │    ├─ 新聞 / 側近書簡 / 勅令用紙 / 台帳 / メモ帳 / 判子・朱肉 / 文鎮 / インク壺 / ランプ
  │    └─ 地図：俯瞰時は静止画スナップショット（地図キャンバスの画像化）
  ├─ 擬似照明オーバーレイ（ランプ位置に応じた放射グラデーション、mix-blend-mode）
  └─ 手元レイヤ（FocusLayer）  正対・変形なし
       ├─ 読む書類（DOM）
       └─ 地図（Phaser のライブキャンバス、パン・ズーム・ホバー可能）
```

- 地図の描画：**Phaser.CANVAS を継続**（AA-09。v3.4 でも同じ。WebGL 化はスパイク結果次第）。地形の重い処理は Web Worker 内の OffscreenCanvas で一度だけ生成し、`ImageBitmap` で受け渡す。
- 地形生成のノイズ：`simplex-noise`（MIT）など、シード付きで決定論的に使えるライブラリ。
- 机上オブジェクトの状態（位置・回転・重なり順・手元か否か）は UI ストアで管理し、`GameState` には入れない。ただし**プレイヤーのメモ（§7）はセーブ対象**。

### 2.3 動作要件

| 項目 | 目標 |
|------|------|
| 解像度 | 1280×720 以上（推奨 1920×1080）。PCブラウザのみ |
| フレームレート | 統合GPU（Ryzen AI 内蔵相当）で俯瞰・手元とも 60fps |
| 地形生成 | 新規ゲーム開始時に 1.5 秒以内（Worker で非同期、進捗は「測量中」演出で隠す）。**SPEC_v3.4.md で 3.0 秒に緩和**（侵食・水文を含むため） |
| ターン遷移演出 | 合計 4〜6 秒。スキップ可能 |
| 初期ロード | 5MB 以内（フォントのサブセット化、テクスチャは WebP） |

## 3. 執務机シーン

### 3.1 カメラ

- 机を手前斜め上から見下ろす固定視点（傾き約 40°）。
- マウス位置に応じたごく弱い視差（±1.5°以内）。酔い防止のため設定で無効化できる。
- ズームはしない。詳細を見るときは「手に取る」（§4.1）。

### 3.2 机上オブジェクト

| オブジェクト | 役割 | 俯瞰での見た目 | 手元での操作 |
|--------------|------|----------------|--------------|
| 地図（測量図） | 都市の視覚情報 | 机の中央奥に広げ、四隅を文鎮で押さえる | パン・ズーム・区画ホバー・メモ留め（§5.6） |
| 新聞 | 世論・事件 | 二つ折りで左手前に置かれる | 広げて読む、紙面をめくる |
| 側近書簡 | 側近の報告 | 封蝋付きの封書が側近ごとに重なる | 封蝋を割って開く、読む |
| 勅令用紙 | 勅令と意図の記入 | 右手前に白紙、横に筆（またはペン）とインク壺 | 書く、タグを付箋で貼る、意図を余白に書く |
| 判子と朱肉 | ターン実行 | 勅令用紙の右に置かれる | 勅令用紙が手元にある時だけ押せる |
| 台帳（帳簿） | 台帳パラメータの記録 | 開いた帳簿として左奥に置かれる | 年ごとのページをめくる（§6） |
| 結果の書類束 | 3段表示＋意図比較 | ターン後に紐で綴じた束として届く | 1枚ずつめくる（§4.4） |
| メモ帳 | プレイヤーの覚え書き | 右奥の小さな手帳と鉛筆 | 書く、ちぎって地図や書類に留める（§7） |
| 既決箱 | 過去ターンの書類 | 机の端の木箱 | 過去のターンの新聞・書簡・結果を取り出して読む |
| ランプ | 光源・雰囲気 | 左奥 | 操作なし（照明演出の基準点） |

### 3.3 配置と重なり

- 各オブジェクトは机上の定位置（ホームポジション）を持つ。置き直したときはホームポジションに戻る。
- 書類は重なり順（z-index と translateZ）を持ち、手に取った書類は最前面に来る。
- 新しく届いた書類は既存の書類の上に重なって置かれ、未読の書類には封蝋や折り目で「未開封」が分かる。

### 3.4 擬似照明と影

- 光源はランプ（左奥）と窓（右上、画面外）の2つ。
- 影は各オブジェクトの高さ（translateZ）と光源の方向から `box-shadow` / `filter: drop-shadow` を計算する。持ち上げると影が広がりぼける。
- 天板全体にランプを中心とした放射グラデーションを重ね、机の手前と端をわずかに暗くする。
- 窓の光の色は、そのターンの新聞の天候記事（N-19）に連動して変える（晴れ：暖色、雨：寒色、雪：白っぽい）。

| 机の暗部 | `#24180D` | 端・手前の陰 |
| 羊皮紙 | `#E8DCC0` | 継承 |

## 4. インタラクション

### 4.1 俯瞰と手元

- 俯瞰でオブジェクトにホバーすると、わずかに持ち上がり（translateZ＋影の拡大）、名前が鉛筆書きの小札で出る。
- クリックで**手に取る**：0.35 秒で手前に引き寄せ、正対させる。背景の机は暗くぼかす（`backdrop-filter` は1枚のみ、性能のため）。
- `Esc`、右クリック、または机の空いた所をクリックで**置く**：ホームポジションに戻る。
- 手元に置けるのは1つ（例外：地図を見ながら書簡を読む「並べ読み」。§4.6）。

### 4.2 勅令の筆記

- 勅令用紙を手に取ると、本文欄と余白（意図欄）が現れる。
- 入力した文字は書道用紙にインクで書かれたように表示する（書体 §8.3、インクのわずかな滲みと濃淡）。入力中は筆記音（§8.1）。
- タグ（対象 / 規模 / 期限 / 優先度）は**付箋**として用紙の上辺に貼る。1枚貼るごとに用紙右下の残り文字数が5減る。
- 残り文字数は用紙の右下に朱で小さく記す。超過すると判子が押せない（判子が持ち上がらない）。
- 意図は余白に鉛筆書きで添える（任意）。

### 4.3 判子とターン実行

- 勅令用紙が手元にあり、文字数が範囲内のときだけ判子が光る。
- 判子をクリック → 判子が持ち上がり、朱肉に一度付け、用紙に押される（約1.2秒）。押印の瞬間に低い打撃音と、用紙がわずかに沈む表現。
- 押した勅令は取り消せない。押す前に確認は出さない（決定の重みは押す所作そのもので表す）。

### 4.4 結果の書類束（3段表示＋意図比較）

- ターン実行後、紐で綴じた書類束が机に届く。
- 束を手に取ると、上から「参謀の解釈」「側近による補正」「実際の結果」「意図比較（宣言時のみ）」の順に重なっている。
- クリックまたはドラッグで1枚ずつめくる。めくった紙は束の裏に回る。
- 差分は朱の訂正線と書き込み（例：「15区画」に線を引き「10」と書く）で示す。
- 意図比較は鉛筆の走り書き風。達成時は小さな丸印、未達時は斜線。
- めくり回数はログに記録（v3.0 KPI）。

### 4.5 ターン遷移シーケンス

判子を押してから次の入力可能状態までを、1つの流れとして演出する（合計4〜6秒、クリックでスキップ可）。

```
1. 押印（1.2s）
2. 勅令用紙が畳まれ、既決箱へ（0.6s）
3. 窓の光が変わる（そのターンの天候に応じて）（0.4s）
4. 地図の更新：変化した区画だけインクが描き込まれていく（1.0〜1.5s、§5.7）
5. 配達：新聞が机の上に置かれ、側近書簡が封蝋付きで届き、結果の書類束が置かれる（1.0s）
6. 台帳の該当年のページに数字が書き込まれる（0.5s）
```

エンディング時は 4 の後に専用演出（成功：町の印章が地図に押される／ゲームオーバー：ランプが消える等）へ分岐する。

### 4.6 並べ読み

- 書簡や新聞を手に取っているとき、地図を左に半分だけ引き寄せて並べられる（`Tab`）。
- 側近報告や新聞が建物や地名に言及しているとき、その語にホバーすると地図上の該当区画が朱でほのかに示される（v3.2 の `relatedEntity` を使う）。
- これにより「新聞・側近・地図の三角測量」（v3.2 §1.8）を机の上の動作として行える。

### 4.7 キーボード操作

| キー | 動作 |
|------|------|
| `1`〜`7` | 地図 / 新聞 / 書簡 / 勅令用紙 / 台帳 / 結果束 / メモ帳 を手に取る |
| `Esc` | 置く |
| `Tab` | 並べ読みの切替 |
| `←` `→` | 紙面・書類・台帳をめくる |

| `Space`（遷移演出中） | スキップ |

## 5. 地図 v3：測量図

### 5.1 基本方針

- 地図は**一枚の測量図**として描く。地形（標高、川、森、平地）は実在の地理として表現し、領地の区画と建物はその上にインクで描き込まれる。
- **ロジックは変えない。** 10×10 の論理グリッドと v3.2 §2.6 の配置ルールはそのまま。論理グリッドを、地形の上の「有機的な区画」に写像して描くだけである。
- 新規ゲーム開始時に、`saveId` をシードとして地形を生成する（決定論）。

### 5.2 地形生成パイプライン（Worker 内、決定論）

> **地形生成は SPEC_v3.4.md §3 に差し替え**（以下は旧案。侵食・水文・地質・植生・段丘を含む v3.4 が優先する）。

```
seed = hash(saveId, "terrain")

1. 標高：fBm（simplex noise 5〜6オクターブ）＋ドメインワーピング、2048×2048 のハイトマップ
2. 盆地化：中央の村域（論理グリッドを写像する領域）を緩やかに平坦化し、すべて建設可能な平地にする
3. 川：地図の高い縁から低い縁へ、流量累積で1本の主流を引く。村域の一辺に沿うように経路コストを調整する（村域内には入れない）
4. 湖・沼：窪地に水をためる（0〜1個）
5. 森：標高・傾斜・川からの距離を元にした森林マスク
6. 地味（肥沃度）：川沿いと低地で高い。描画では畑の色の濃さにのみ使う
7. 地名：地形の特徴から区画名と周辺地名を生成（§5.5）
```

> 地形は村域の外側にのみ効く。論理グリッド100区画はすべて建設可能であることを保証し、建設可能区画数（＝バランス）は v3.2 から変わらない。

### 5.3 論理グリッドと区画の写像

- 村域を 10×10 に分割し、各セルの頂点をシード付きでわずかにずらす（ジッター）。さらに Lloyd 緩和を1〜2回かけた多角形にして、手で測量したような不揃いの区画にする。
- 区画の境界は細いインクの破線で描く。
- 道路（v3.2 の `road`）は、区画の境界に沿って A* で経路を引き、Catmull-Rom 曲線で滑らかにして二重線で描く。
- 建物は区画の中央付近に、絵記号（ピクトグラム）として描く（§5.4）。

### 5.4 描画レイヤと様式

測量図の様式は「古い官製の測量図」。彩度は低く、インクの線と淡彩の水彩で構成する。

| 順 | レイヤ | 内容 | 更新タイミング |
|----|--------|------|----------------|
| 1 | 紙 | 羊皮紙の地、紙の繊維、縁の焼け、折り目の線 | 生成時 |
| 2 | 淡彩 | 標高に応じた水彩の塗り（低地：くすんだ緑、高地：黄土、山頂：灰） | 生成時 |
| 3 | 陰影 | ハイトマップからの陰影（左上光源、乗算） | 生成時 |
| 4 | 等高線 | 一定間隔の細い茶インク線、5本ごとに太線 | 生成時 |
| 5 | 水系 | 川は青インクの二重線と内側の淡い水彩、湖は水平のハッチング | 生成時 |
| 6 | 森 | 樹木記号の点描（シード付き配置） | 生成時 |
| 7 | 区画 | 破線の境界、畑は縞のハッチング、空き地は無地 | 毎ターン |
| 8 | 道路 | 二重線 | 毎ターン |
| 9 | 建物 | 絵記号（17種、§10.2） | 毎ターン |
| 10 | 地名 | 地名・区画名（§5.5）、等高線に沿わせない水平配置 | 生成時＋毎ターン |
| 11 | 装飾 | 方位記号、縮尺、表題（領地名・測量年＝ターン）、余白の注記 | 毎ターン |
| 12 | 書き込み | ~~亀裂印~~（廃止：I-32）、プレイヤーのメモ（§7） | 毎ターン |

### 5.5 地名の生成

- 地形の特徴から地名を作る：川沿い、北の丘、杉の森の外れ、沼の手前、南の平地、など。
- 区画には「方角＋地形＋区画」の名前を付ける（例：「川沿いの東区画」「北の丘の麓」）。
- 新聞の `{place}` スロット（v3.2 §1.4）は、この区画名と地名から埋める。新聞・側近報告・地図が同じ地名を共有することで、並べ読み（§4.6）が成立する。

### 5.6 手元での地図操作

| 操作 | 動作 |
|------|------|
| ホイール | ズーム（村域全体 〜 区画1つ程度まで、3段階程度） |
| ドラッグ | パン |
| 区画にホバー | 区画名と、そこにある建物の名前を鉛筆の小札で表示。台帳にない派生指標は表示しない |
| 区画をクリック | その区画に関係する過去の記事・側近報告を一覧（既決箱から検索） |
| メモを留める | メモ帳の紙を区画にドラッグして留める（§7） |

### 5.7 更新の演出（インクの描き込み）

- ターン遷移時、変化した区画だけを描き込む。新しい建物は輪郭線が引かれてから記号が描かれ、道路は線が伸びていく。
- 今ターン描き込んだ線は濃い新しいインク、過去の線は古いインクの色で描く。これにより「何が最近変わったか」が地図を見るだけで分かる。
- 建物が失われた場合は、記号の上に二重線を引いて消す（消しゴムでは消さない）。

### 5.8 見た目と実態の乖離（v3.0 §8.3, §12.7 の継承）

> **廃止（亀裂印・注記の部分）。DECISIONS I-32 に従い、空洞は地図に一切出さない**（開示後も同じ見た目）。地図に描くのは `visual_state` のみで、空洞は新聞の投書と側近報告でしか知れない。以下の第2項は旧案として残す。

- 地図に描かれるのは `visual_state`（見た目）。実態は描かない。
- 側近報告で空洞・塩漬けが開示された建物には、地図の記号の横に朱で小さな亀裂印と、鉛筆の注記（例：「中は空との報」）を描き込む。
- 開示されていない乖離は地図に一切現れない（v3.2 §1.8 の三角測量を維持）。

### 5.9 実験オプション：測量の遅れ（既定は無効）

地図を「測量官の報告に基づく文書」として扱い、側近の能力や隠蔽によって地図の更新が遅れる・欠けるモード。地図の信頼性も揺らぐため中核仮説に強く効くが、v3.0 の「地図は見た目を正しく描く」前提を変える。**P0 では既定で無効**とし、プレイテストで比較できるフラグとして実装する。

| 要素 | 内容 |
|------|------|
| 表題の測量年 | 最後に正しく測量されたターン |
| 未測量の区画 | 前回の状態のまま、古いインクで描かれる |
| 隠蔽 | 野心高・忠誠低の側近が担当すると、悪化した区画が描き込まれない |

## 6. 台帳（帳簿）

- 台帳パラメータ（人口・国庫・幸福度・インフラ・汚職率・政治資本）は、開いた帳簿として机の左奥に置く。v3.2 §2.2 の「台帳（可視）」をそのまま物体にしたもの。
- 1ページ＝1年。表の形で6項目を手書き風に記す。前年からの増減を小さく添える。
- めくると過去の年を見られる。直近10年は小さな折れ線（鉛筆の手描き風）で推移を示す。
- 派生指標は帳簿に載らない（v3.2 踏襲）。
- 汚職率など、側近報告に依存する値の扱いはロジック側の仕様に従う（本書では変えない）。

## 7. メモ機能（新規）

情報を「反芻する」行為を、机の上の作業として支える。

- 机にメモ帳と鉛筆がある。手に取るとメモを書ける（1枚 60 文字まで）。
- 書いたメモはちぎって、地図の区画・新聞の記事・側近書簡に**留められる**。留めたメモは小さな紙片として表示され、ホバーで内容が読める。
- メモはセーブデータに保存する（`GameState` とは別の `PlayerNotes`。ゲームロジックには一切影響しない）。
- メモの内容は LLM にも新聞にも渡さない。
- KPI：メモの作成数、留め先の分布（地図・新聞・書簡）。三角測量をしているかの指標になる。

## 8. 音とタイポグラフィ

### 8.1 効果音（すべて CC0 または自作）

| 場面 | 音 |
|------|----|
| 書類を手に取る / 置く | 紙の擦れ、紙が机に触れる音 |
| 新聞を広げる / めくる | 大きな紙の音 |
| 封蝋を割る | 小さく乾いた割れる音 |
| 勅令の筆記 | 筆の擦れる音（入力1文字ごと、間引いて再生） |
| 付箋を貼る | 軽い紙の音 |
| 判子 | 低い打撃音＋わずかな余韻 |
| 地図の描き込み | ペン先の擦れる音 |
| 配達 | 扉の向こうの足音、書類が置かれる音 |
| 環境音 | ランプの微かな音、窓の外の天候（雨、風）。小さく常時 |

- 音量は 主音量 / 効果音 / 環境音 の3つを設定で調整可能。既定は控えめ。

### 8.2 アニメーション原則

- 物体の動きは「重さ」を感じるイージング（立ち上がりは遅く、着地はわずかに沈む）。
- 同時に動く物体は3つまで。
- 「動きを減らす」設定（OSの `prefers-reduced-motion` に追従）では、移動を即時表示またはフェードに置き換える。

### 8.3 書体（v3.0 §12.4 を拡張）

| 要素 | 書体 | ライセンス |
|------|------|------------|
| 新聞の本文・UI全般 | Noto Serif JP / Noto Sans JP（継続） | OFL |
| 新聞の見出し・地図の表題・帳簿の見出し | しっぽり明朝 B1（Shippori Mincho B1） | OFL（要確認） |
| 勅令の本文（筆記） | 筆書き風の書体を候補選定（OFL のもの）。見つからなければ Noto Serif JP の太字にインク表現 | OFL |
| 側近書簡・メモ・地図の注記 | Klee One（手書き風） | OFL（要確認） |

- 側近ごとの筆跡の差（v3.0 製品版項目）は、P0 では書体を2種（Klee One と Noto Serif JP）に分けて表現する。
- 日本語書体はサブセット化して読み込む（使用文字は `messages.ts` とテンプレートから抽出）。
- ライセンスは採用前に配布元で確認し、`docs/ASSETS.md` に記録する。

## 9. アクセシビリティ・性能・フォールバック

- **平面モード**：設定で3D表現を無効化できる。机は真上から見た配置になり、書類は平面のパネルとして並ぶ。ロジックと情報は同一。性能の低い環境と、立体表現が苦手なプレイヤー向け。
- **文字サイズ**：手元の書類の文字サイズを3段階で変更可能。
- **色覚**：朱の差分表示には必ず線（訂正線・印）を併用し、色だけに頼らない。
- **性能の自動調整**：フレームレートが一定時間 45fps を下回ったら、視差・ぼかし・環境の微動を自動で切る。
- **WebGL 非対応**：地図は Canvas 2D で生成済みの画像を表示し、ズームは画像の拡大で代替する。

### 11.1 型の追加

```ts
type TerrainData = {
  seed: number;
  heightmap: Float32Array;       // 2048×2048 を間引いた解像度でも可
  river: Polyline;
  lakes: Polygon[];
  forestMask: Uint8Array;
  fertility: Uint8Array;
  parcels: Parcel[];             // 100区画（論理グリッドと1対1）
  toponyms: Toponym[];
};

type Parcel = {
  gridIndex: number;             // 0..99
  polygon: Point[];
  name: string;                  // 「川沿いの東区画」
};

type PlayerNote = {
  id: string;
  text: string;                  // 60文字まで
  turnCreated: number;
  attachedTo: Option<
    | { kind: "parcel"; gridIndex: number }
    | { kind: "article"; turn: number; articleId: string }
    | { kind: "aideReport"; turn: number; aideId: string }
  >;
};

type DeskUiState = {             // UIストアのみ。セーブしない
  focused: Option<DeskObjectId>;
  sideBySide: boolean;
  order: DeskObjectId[];
};
```

### 11.2 決定論と状態の分離

- `TerrainData` は `saveId` から常に同じものが生成される。セーブには `seed` のみを保存し、ロード時に再生成する。
- 地名は `TerrainData` に含まれ、新聞の `{place}` スロットはこれを参照する。新聞生成（v3.2 §1.6）の決定論を壊さないよう、地名一覧は新聞生成より前に確定させる。
- 表現層は `GameState` を読むだけ。`PlayerNotes` と設定以外を書き込まない。

### 12.1 フェーズ

| フェーズ | 内容 | 目安 |

| U3 | 測量図：地形生成 Worker、区画写像、道路、絵記号17種、地名、手元の地図操作、俯瞰用スナップショット | 1.5〜2週間 |

### 12.2 推奨する進め方

- P1（ロジック）は v3.2 までの仕様で先に完成させる。本書はロジックに触れないので並行して設計できる。
- UI はまず**平面モード**で一通り遊べる状態を作り、そこに U1〜U4 を重ねる。平面モードはフォールバックとして最後まで残るので、無駄にならない。
- 測量図（U3）は単独で価値が高いので、時間が足りない場合は U4 の演出を削る。

### 12.3 P0 で削ってよいもの（優先度低い順）

1. 環境音と窓の光の天候連動
2. 並べ読み時の地図ハイライト
3. 地図の描き込みアニメーション（即時描画で代替）
4. 側近ごとの書体の差

## 13. テストと KPI の追加

### 13.1 テスト

- 地形生成の決定論：同じ `saveId` で同じ `TerrainData`（ハッシュ比較）
- 村域の100区画がすべて建設可能（水・急傾斜を含まない）
- 区画の多角形が重ならず、隙間がない
- 道路の経路が区画の内部を横切らない
- 地名の一意性（同一区画名の重複なし）と、新聞の `{place}` が地名一覧から埋まること
- 平面モードと3Dモードで、表示される情報が同一であること
- `prefers-reduced-motion` で遷移演出が短縮されること
- パフォーマンス計測：俯瞰・手元・ターン遷移でのフレームレート（統合GPU環境で手動計測）

### 13.2 KPI（v3.0 §15、v3.2 §3.2 に追加）

- 手に取った回数（オブジェクト別）と、手元での滞在時間
- 並べ読みの使用回数
- 地図の区画ホバー・クリック回数
- メモの作成数と留め先の分布
- 平面モードの選択率（立体表現が負担になっていないか）
- 遷移演出のスキップ率（長すぎないか）
